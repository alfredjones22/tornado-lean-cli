# Native Tornado witness boundary

`Tornado/Protocol/TornadoWitness.lean` computes and validates the first 49
signal slots of the pinned Classic Tornado `Withdraw(20)` circuit in Lean.
These slots are the constant `one`, six public inputs (`root`,
`nullifierHash`, `recipient`, `relayer`, `fee`, `refund`), and 42 private inputs
(`nullifier`, `secret`, 20 path elements, 20 path indices). The slot order was
checked against `signalName2Idx` in the circuit pinned by SHA-256
`3ddd61dbff09caeec82d8edde95c674a3c34f9e66b1fe9f2c8783e72fe536f98`.

The module recomputes the note's Pedersen commitment and nullifier hash from
its 31-byte preimages, checks a 20-level MiMC membership path, binds its root
to a caller-supplied expected root, and rejects out-of-range address, fee,
refund, and sibling values. The expected root is **not** authenticated here:
the caller must check it against the contract's accepted root history using a
trusted chain view. Likewise, this module does not decide whether the note is
spent or whether a relayer will honor a fee.

`tests/TornadoWitness.lean` derives the public test note with native Lean
secp256k1/Pedersen code, builds its one-leaf Merkle tree in native Lean, and
compares every one of the 49 generated slots against the pinned full SDK
witness in `fixtures/groth16-tornado-r1cs.json`. Eight malformed inputs are
rejected. Four kernel-checked properties prove the prefix length and the
placement of the root, nullifier hash, and private nullifier; `#print axioms`
reports only Lean's standard `propext` and `Quot.sound` axioms.

## Full witness generator and its limits

The pinned circuit has 28,300 witness variables, 28,275 R1CS constraints,
36,528 signal records, 2,342 components, 39 JavaScript templates (85,489
characters), and the `nbits` helper function. `WitnessVM.lean` implements
the required typed primitive templates and signal graph in native Lean. It
fills all 36,528 signals and 28,300 witness slots, authenticates the decoded
R1CS constraints, and checks every equation before returning a witness. Four
public full-witness tests pass, including an exact match of every slot against
the pinned SDK witness. See [the full VM scope](WITNESS_VM_SCOPE.md).

The graph was generated by a development extractor from the pinned Circom
asset. The extractor and handwritten Lean translations of point and mux
semantics remain correspondence assumptions, with finite test evidence rather
than a universal equivalence theorem for every possible input. The 49-slot
prefix still accepts a caller-supplied root; neither module proves that root
is recent, accepted on-chain, or unspent. Proof generation and Groth16 pairing
verification remain separate requirements.

No JavaScript is called by the Lean runtime module or its parity test. The
pinned full witness used as the comparison oracle was generated upstream and
is public test data; runtime witness production itself is native Lean.
