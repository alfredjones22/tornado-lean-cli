# Protected native signer boundary

Experimental invoice/multi-note deposits, owner-key batch withdrawals and smart-account recovery use this boundary. Lean passes a protected key-file path or a public interactive-session source alias and the exact transaction or operation signing digest to C. No private-key bytes are returned to Lean. The C bridge returns a public identity and checked low-S signature; Lean binds them to the reviewed sender and exact serialized transaction or UserOperation. A protected journal/reservation must precede executable exposure. Simple7702 persistent delegation is journaled before estimation can receive its signature; signed final withdrawal simulation is also executable exposure.

The boundary consists of [`tornado_private_io.c`](../native/tornado_private_io.c), [`tornado_secret_sign.c`](../native/tornado_secret_sign.c), [`NativeSigner.lean`](../Tornado/Runtime/NativeSigner.lean), and unmodified [libsecp256k1 v0.8.0 source](../native/vendor/libsecp256k1/UPSTREAM.md). The C importer applies the same protected-file owner, mode, symlink, hard-link and stability checks as other private-file reads, with a 1,024-byte key-file limit. It also rejects macOS ACL grants; Linux relies on mode bits and does not explicitly inspect every ACL implementation. It uses a locked native page, sets process core-dump soft and hard limits to zero, requests no-dump page handling where supported, randomizes each libsecp256k1 context from OS entropy, and clears/unlocks/unmaps the page on every exit. It rejects failed memory controls, invalid keys, failed signatures, recovery IDs 2 or 3, and signatures that fail verification or recover a different public key.

The signer now returns fixed, actionable diagnostic categories for a missing key file, unsafe path or file metadata, excess size, malformed 0x-prefixed 32-byte hex content, and an invalid secp256k1 scalar. A missing-file diagnostic asks the user to check the path; an unsafe mode diagnostic suggests `chmod 600`; a format diagnostic says that the file must contain a raw key rather than an encrypted JSON keystore. A short signing digest is rejected separately. Memory controls, native entropy, secp256k1 setup, signing, verification, and recovery also have fixed stage diagnostics. Symlinks, multiple hard links, group/other access, special mode bits, and macOS ACL grants each fail closed. The macOS ACL diagnostic means the policy could not be verified; it does not assert that a grant was found, since inspection failure also blocks. Diagnostic strings contain no key bytes, file path, digest, or OS error number; they identify the stage of failure rather than echoing file contents or proving that an RPC or wallet state is safe. The focused test uses only synthetic public fixture keys and checks the diagnostic text and the absence of a unique secret-like sentinel.

The source is pinned to the upstream release commit and verified against an archive hash in the [vendor manifest](../native/vendor/libsecp256k1/UPSTREAM.md). The focused native test compares a protected public fixture key's address, signature and complete transaction bytes with independent Lean and pinned viem vectors. It also exercises malformed, zero, out-of-range, missing, wrongly permissioned, symlinked, hard-linked, oversized, and wrong-type synthetic key files, with a macOS ACL case where supported. The deposit effect test checks that sender mismatch, journal-write failure and ambiguous broadcast stop before a second send. The full verifier checks the C FFI allowlist and vendor source digest.

This is a stronger secret boundary for protected owner-key routes and dry-run address lookups, not a whole-wallet certificate. libsecp256k1, the C wrapper, compiler, OS memory behavior, protected file system, and the security of the key file remain trusted. Clearing is best effort; there is no theorem proving complete erasure or constant-time behavior of the compiled program. Separate finite [Sepolia ETH execution results](SEPOLIA_LIVE_TESTS.md) exercise connected owner-key routes; independent external security auditing remains outside current validation coverage. Note creation and the isolated withdrawal prover/note-derived signer put spendable secrets in Lean-managed memory. Their variable-time, nonzeroizing implementation is used by experimental withdrawal commands; this native key-file signer does not harden that separate note path.

## Interactive account keys

`--non-interactive` requires a protected account key file for deposits, batch
withdrawals and live recovery; it never opens this key-entry prompt. A recovery
dry-run can instead use public `--owner` without a private key. The flag skips
typed send/delegation confirmation, while retaining the printed reviews and
the native signing and journal checks described here.

Omitting a required account key-file argument opens `/dev/tty` with echo disabled. Key text is parsed and checked inside C in the same locked native region policy as file keys; it is not a Lean String/ByteArray, command-line argument, environment value or temporary key file. A random command-local public source alias lets existing signing calls use that native session. The alias is not a file and cannot unlock anything in another process. Its directory anchors the same protected reservations as file-based commands. The CLI clears the session in a finalizer and at normal process exit. Signal interruption during entry restores the terminal and clears the pending input; pasted typeahead is flushed before later approval prompts. Ordinary commands use this single-threaded session; it is not a general concurrent key-vault API. Abrupt exits rely on OS reclamation and the existing no-dump protections.

The trusted FFI additionally includes `tornado_secure_prompt_key` and `tornado_secure_clear_prompt_key`. Public-fixture PTY tests cover hidden input, signing, no disk key, pasted-approval isolation, invalid input, interruption, EOF, no-terminal errors and terminal restoration. These tests do not establish complete erasure or end-to-end correctness.
