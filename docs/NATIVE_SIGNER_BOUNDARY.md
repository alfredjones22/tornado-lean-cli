# Protected native signer boundary

Experimental invoice/multi-note deposits, owner-key batch withdrawals and smart-account recovery use this boundary. Lean passes a protected key-file path and the exact transaction or operation signing digest to C. No private-key bytes are returned to Lean. The C bridge returns a public identity and checked low-S signature; Lean binds them to the reviewed sender and exact serialized transaction or UserOperation. A protected journal/reservation must precede executable exposure. Simple7702 persistent delegation is journaled before estimation can receive its signature; signed final withdrawal simulation is also executable exposure.

The boundary consists of [`tornado_private_io.c`](../native/tornado_private_io.c), [`tornado_secret_sign.c`](../native/tornado_secret_sign.c), [`NativeSigner.lean`](../Tornado/Runtime/NativeSigner.lean), and unmodified [libsecp256k1 v0.8.0 source](../native/vendor/libsecp256k1/UPSTREAM.md). The C importer applies the same protected-file owner, mode, symlink, hard-link and stability checks as other private-file reads, with a 1,024-byte key-file limit. It also rejects macOS ACL grants; Linux relies on mode bits and does not explicitly inspect every ACL implementation. It uses a locked native page, sets process core-dump soft and hard limits to zero, requests no-dump page handling where supported, randomizes each libsecp256k1 context from OS entropy, and clears/unlocks/unmaps the page on every exit. It rejects failed memory controls, invalid keys, failed signatures, recovery IDs 2 or 3, and signatures that fail verification or recover a different public key. Errors are fixed strings and do not contain key bytes.

The source is pinned to the upstream release commit and verified against an archive hash in the [vendor manifest](../native/vendor/libsecp256k1/UPSTREAM.md). The focused native test compares a protected public fixture key's address, signature and complete transaction bytes with independent Lean and pinned viem vectors. The deposit effect test checks that sender mismatch, journal-write failure and ambiguous broadcast stop before a second send. The full verifier checks the C FFI allowlist and vendor source digest.

This is a stronger secret boundary for protected owner-key routes and dry-run address lookups, not a whole-wallet certificate. libsecp256k1, the C wrapper, compiler, OS memory behavior, protected file system, and the security of the key file remain trusted. Clearing is best effort; there is no theorem proving complete erasure or constant-time behavior of the compiled program. Funded live testing and independent external security auditing are outside current validation coverage. Note creation and the isolated withdrawal prover/note-derived signer put spendable secrets in Lean-managed memory. Their variable-time, nonzeroizing implementation is used by experimental withdrawal commands; this native key-file signer does not harden that separate note path.
