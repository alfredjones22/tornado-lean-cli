# Native history and compliance report scope

`Tornado/Cli/History.lean` implements the read-only `history` and `compliance report` surfaces. The CLI selects one note from a protected backup, computes its commitment and nullifier hash locally, verifies the selected pool against the pinned catalog/bootstrap, and reconstructs that pool through bounded Saga/RPC history. It then asks the same configured RPC for the captured block's `isSpent` result, re-reads the **whole selected pool's logs at each selected event block**, and binds the exact event fields and global log index to a successful receipt and block hash. A final captured-head hash read detects a changed RPC view during the report.

The `eth_getLogs` filter contains only the public pool address and exact block range. It never contains the note commitment or nullifier. The `isSpent(bytes32)` `eth_call` **does send the selected note's nullifier hash to the configured RPC**. This matches the pinned TypeScript command and should be disclosed to users choosing a third-party RPC. The command never prints the note or preimage. `history` prints only pool, deposit, spent status and optional withdrawal information. `compliance report` writes a redacted JSON report through exclusive protected-file creation; the unspent nullifier hash is withheld from that file. The report still links a deposit to the operator, so it is stored with mode 0600.

The network result is **provider-checked evidence, not consensus verification**. Ethereum RPC and Saga can omit logs; the on-chain root/leaf-count check detects missing deposits, while the selected-note `isSpent` call detects a missing selected withdrawal. A malicious provider can falsify all replies consistently. The code does not certify deployed pool bytecode, verifier, or operator state. A pool catalog entry alone does not authenticate the contract implementation.

`--assets-dir` imports a selected pool's pinned local UI history snapshot. `--history-cache-dir` reads and writes public history through protected, content-addressed chunks and a compare-and-replace index. Both paths check the checkpoint count and root against same-block RPC claims; native caches also check the checkpoint block hash and replay the legacy overlap. A mismatched checkpoint is discarded. Without a usable checkpoint, `HistorySync` starts from the pinned registration block and uses Saga or bounded RPC fallback. An old pool whose Saga coverage is unavailable can exceed the native 2-million-block fresh RPC scan window and fail closed. Remote pinned snapshot download is not implemented. See [snapshot scope](HISTORY_SNAPSHOT_SCOPE.md). `compliance report` creates the output only after all checks complete.

Focused offline verification: `lake build Tornado.Cli.History` and `lake env lean --run tests/History.lean`. Fixtures cover unspent/spent output, redacted JSON, exact-block full-pool filters, successful receipt and block binding, an omitted deposit, omitted withdrawal with `isSpent=true`, reverted receipt, wrong chain, and a changed head hash. The compiled `history_snapshot_test` covers pinned imports, cache integrity, reorg reset and index CAS conflicts.
